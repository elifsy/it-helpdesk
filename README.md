# 内部 IT 报修平台

正式部署：<https://ams.tzme.net>。前后端分别在 `ams-backend`、`ams-frontend` 两个 tmux 会话运行，配置和维护命令见 [SERVER-DEPLOYMENT.md](SERVER-DEPLOYMENT.md)。

支持 trycloudflare 临时公网预览：本地服务启动后双击 `preview.cmd` 获取 HTTPS 地址，双击 `stop-preview.cmd` 停止预览。保留钉钉免登，使用方式见 [TRYCLOUDFLARE-PREVIEW.md](TRYCLOUDFLARE-PREVIEW.md)。

手机端按屏幕宽度自动切换为单列页面和固定底部导航，左上角“全部功能”保留当前账号获准访问的完整菜单；工单中心与资产台账使用可点击卡片。布局使用媒体查询，支持缺少容器查询能力的钉钉内嵌浏览器，并留出底部安全区。

知识库搜索支持输入联想：按标题和摘要包含匹配，输入停顿后显示最多 5 条候选并高亮匹配文字，可点击或用上下键和 Enter 选择搜索。用户端与管理端共用此功能，用户端候选遵循当前分类筛选。

关单后自动沉淀知识草稿，支持 IT 整理、权限控制发布、撤回、归档及历史工单补充沉淀，详见 [KNOWLEDGE-CAPTURE.md](KNOWLEDGE-CAPTURE.md)。

资产台账支持新增、重命名和删除空分类，以及调整现有资产归类；领用、借用、更换、归还和更换审批均使用左侧分类、右侧设备卡片的选择界面，支持搜索和单选高亮。使用与升级说明见 [ASSET-CATEGORIES.md](ASSET-CATEGORIES.md)。

资产台账支持每页 15 台的分页、组合筛选及详情返回原页码。导航已移除“二维码标签”和“派单队列”重复入口；普通用户在“我的服务”中使用资产服务和知识库，不再显示“资产与知识”分组。详见 [ASSET-PAGINATION.md](ASSET-PAGINATION.md)。

点击台账中的设备编号、名称或设备行，可进入独立详情页，查看资料与履历，并进行编辑、查看二维码和调整分类。详见 [ASSET-DETAIL.md](ASSET-DETAIL.md)。

新增与编辑资产共用完整资料表单：名称、型号（选填，最多128字）、分类、SN、位置、购置日期、维保方式、维保到期、设备状态及备注。新增时另填资产编号；型号支持台账检索及设备选择搜索，详情可查看和修改。已有数据库启动时仅增加可空的 `it_asset.model` 字段，原有资料保留。

新增或编辑时填写有效存放位置，待入库设备会自动改为闲置；仅填空格不触发，其他状态保持原值。后端保存时再次执行同一规则，并沿用编辑版本和分配、借用保护。

工作台统计卡片可点击：待受理、处理中和超时预警进入对应工单筛选；满意度进入统计看板。处理中包含已受理、处理中、待用户和待供应商四种状态；超时预警排除已关闭、已驳回和已撤销工单。筛选、搜索及页码写入页面地址，支持刷新和浏览器前进/返回。工单接口的 `status=PROCESSING`、`status=OVERDUE` 分别提供上述组合筛选，原有精确状态查询仍可使用。

统计看板中“问题设备 Top 5”的每项及“资产总数、在用、闲置、借出中”均可点击弹窗查看明细，支持报修分页与资产搜索。详见 [STATS-DETAILS.md](STATS-DETAILS.md)。

用户首页、我的工单和详情会显示当前接单 IT 及前方待处理工单数量，详情支持手动和定时更新。统计规则与升级说明见 [TICKET-QUEUE.md](TICKET-QUEUE.md)。

公司内部 IT 服务台：员工报修、工单流转、资产领用/借用/更换、扫码直达设备、知识库自助、统计看板。
本仓库是按《内部IT报修平台-需求蓝图》落地的**可运行工程**，不是界面原型。

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Vue 3.5 + Vite 5 + TypeScript + Vue Router + Pinia + Axios + ECharts 5 |
| 后端 | Spring Boot 3.3 + Java 17 + MyBatis 3 + Spring Validation + JJWT |

## 快速启动

> **Windows 本地最快**：双击 `start.cmd`，首次输入一次 MySQL 密码即可（自动建库导数据、起前后端、开浏览器）。
> 其他情况见 [LOCAL-RUN.md](LOCAL-RUN.md)。
> 没有 Redis 时启动加 `--helpdesk.redis-enabled=false`，会自动降级，功能不受影响。

### 方式一：Docker 一键（推荐）

```bash
cp .env.example .env          # 按需修改 JWT_SECRET / 钉钉参数
docker compose up -d --build
```

- 前端：<http://localhost>
- 后端：<http://localhost:8080/api>
- MySQL 首次启动会自动执行 `sql/schema.sql` 与 `sql/seed.sql`

### 方式二：本地开发

```bash
# 1. 起依赖（也可用本机已装的 MySQL 8 / Redis 7）
docker compose up -d mysql redis

# 2. 导入表结构与种子数据
mysql -uroot -p < sql/schema.sql
mysql -uroot -p < sql/seed.sql

# 3. 后端
cd server && mvn spring-boot:run

# 4. 前端
cd web && npm install && npm run dev
# 打开 http://localhost:5173
```

## 核心链路

```
员工提交报修（4 项必填）
  → 服务端按「影响范围 × 工作影响」算优先级（信息安全强制 P1）
  → 生成工单号 + 解决时限（Redis 按天自增，不重号）
  → 工作台通知所有受理员（站内 + 钉钉工作通知）
  → 工程师点击受理（自动由本人接单并进入处理中）→ 处理记录 → 提交完成（确认问题分类）
  → 员工确认「已解决」+ 星级 → 关单，统计与看板更新
```

工程师点击“受理”后，系统立即绑定当前登录账号，记录受理与接单时间，更新排队数量，并通知报修人由谁处理。页面直接提供“添加处理记录”和“提交完成”。旧版已受理但尚未分配工程师的工单也支持直接受理接单。多人同时抢同一张工单时只有一人成功，不会重复分配或发送受理通知。

资产侧：扫码或「资产服务」入口 → 领用/借用/更换/归还申请 → 资产管理员审批 → 自动改写资产状态、使用人与履历；更换会回收旧机并把未结工单转移到新机。

**设备购入申请（购物车）**：领用时找不到合适设备 → 员工在首页/「资产服务」点「购入申请」，用与领用相同的设备选择弹窗，
像购物车一样加入多个型号（可调台数），填事由一起提交；提交时每台会拆成一条明细，审批一次、逐台流转：

```
申请单 PENDING ──审批（可走钉钉）──► APPROVED
                                       ├─ 明细 PENDING ──库存配发（选一台现成设备）──► 待领取 ──确认交付──► 已交付
                                       │              └─转采购（填 ERP）──► 已申请采购 ──到货配发──► 待领取 ──确认交付──► 已交付
                                       └─ 全部明细已交付 ──► 整单 COMPLETED
```

- IT/管理员在「采购管理 → 待处理」里逐条明细点「库存配发 / 转采购 / 到货配发 / 确认交付」，互不影响：
  库存够的直接配发并通知领取，不够的单独填 ERP 单号，到货后再单独指定资产交付。
- 明细进入「待领取」时该资产即被预留（资产列表显示「待领取 · 姓名」），别人不能抢；交付后资产绑定到申请人并写履历。
- 采购目录在「采购管理 → 采购目录」维护（增删改、启停、卡片图标），员工只能申请启用的型号。
- 资产台账的「新增资产 / 编辑设备」也用同一套图标选择器（`components/DeviceIconPicker.vue`），图标存 `it_asset.icon`；
  不指定就按设备名称与分类自动匹配。资产台账列表、设备详情、领用/报修的设备选择弹窗都会使用这个图标。
- 审批走钉钉：在「系统管理 → 钉钉审批 → 设备购入」配 processCode 即启用，未配置则走系统内审批。

**线下交接确认（可选）**：「运行配置 → 资产交接确认」按业务勾选分类后，命中的分类审批通过不会立刻改资产，
而是先进入待领取 / 待归还，由 IT 或管理员在「资产申请」页点「确认已领取 / 确认已归还」才真正落地；
未勾选的分类保持原逻辑——审批通过即执行。
更换是两段：先「确认已归还旧机」（旧机回库），再「确认已领取新机」（新机配发给申请人、转移未结工单）。
待领取期间该设备视为「已被该申请人预留」：资产列表返回 `reservedBy / reservedRequestNo`，卡片显示「待领取 · 姓名」并隐藏领用/借用入口，
任何人再申请都会被 409 拦住（提示占用单号）。审批中（未通过）的单子不算占用，仍允许多人同时申请同一台。

设备选择统一用弹窗（`components/AssetPicker.vue`）：左侧分类、右侧卡片、支持搜索，本人领用/借用的设备标「我的设备」并排在前面。
归还范围同时包含「本人借用中」和「本人领用中（在用）」的设备；归还领用设备审批后解除使用人、设备回库变闲置。
报修页的「关联设备」也用同一个弹窗（不再是下拉框），选中后仍会做重复工单校验。

**防重复提交**：同一人对同一台设备同时只能有一张未结工单（状态非关闭/驳回/撤销即视为未结）。
报修页选中设备后会先查一次并给出提示条（可直接跳到原工单），提交时后端再校验一次；
资产申请同理，同一人对同一设备只允许一条待审批（PENDING）申请。
四个资产入口（领用/借用/更换/归还）的「可选 N 台」和设备选择弹窗都会排除本人待审批的设备，
设备清单里这类设备标注「申请待审批」且不再显示申请按钮——同一台设备仍可被多个人同时申请。

优先级矩阵与设备可用操作分别收敛在 `PriorityCalculator` 和 `AssetService.actions()`，前后端不各写一套。

## 数据库

13 张表：`it_attachment`、`sys_dept`、`sys_user`、`it_asset`、`it_asset_history`、`it_asset_request`、
`it_ticket`、`it_ticket_event`、`it_ticket_record`、`it_kb_article`、`it_solution_code`、`it_notify`。

设计要点：

- **工单与事件分离**：`it_ticket` 存当前状态，`it_ticket_event` 存完整流转轨迹（举证与时效分析用）。
- **资产与履历分离**：状态在 `it_asset`，每次领用/借用/维修/调拨写 `it_asset_history`。
- **关单以问题分类为准**：提交完成时必须确认一级/二级问题分类（默认带出报修时的分类，可纠正），
  统计与知识沉淀都读这个分类。历史上的「解决代码」已停用：`it_ticket.solution_code` 列与
  `it_solution_code` 字典保留历史数据，不再写入、不再在界面维护。
- **单号不靠数据库自增**：Redis 按天 `INCR`，多实例部署也不会重号；Redis 不可用时降级为时间戳。

## 钉钉接入

1. 钉钉开放平台创建**企业内部应用**，拿到 `AppKey` / `AppSecret` / `AgentId` 与 `CorpId`。
2. 应用首页地址填前端地址（**必须手机 4G 可访问**），配置服务器出口 IP 白名单。
3. 申请权限：通讯录只读、工作通知、扫码。
4. 通讯录同步到 `sys_user`（本仓库用种子数据；正式环境接通讯录事件订阅 + 每日对账，离职当日停用并转派未结工单）。
5. `.env` 设置 `DINGTALK_ENABLED=true` 及各项参数，重启后端。

### 资产审批走钉钉（可选，轮询同步）

开启后，资产申请不再由本系统审批，而是提交时发起一条钉钉审批实例，结果由后端定时轮询回来再执行资产动作。

1. 钉钉开放平台给该应用勾选**审批**权限（沿用现有应用即可，无需新建）。
2. 钉钉审批后台建审批模板（领用/借用/更换/归还各一条），表单控件名必须与系统一致：
   `申请单号 / 业务类型 / 资产编号 / 资产名称 / 资产分类 / 申请人 / 部门 / 申请事由 / 约定归还日期`。
3. 打开「系统管理 → 钉钉审批」页：总开关、联调模式、轮询间隔，以及**五类业务各自的**模板 `processCode`
   与**表单字段映射**（系统字段 → 钉钉控件名，留空用默认名，填 `-` 表示不传该字段）。
   业务类型：资产领用 / 资产借用 / 资产更换 / 归还设备 / **设备购入**（购入的表单字段为单号、业务类型、
   设备名称、资产分类、申请人、部门、申请事由）。未填 processCode 的业务继续走系统内审批，可以一类一类切。
4. 更换业务需在提交申请时预选「替换设备」（审批端选不了台账），通过后自动换机、旧机回库、转移未结工单。
   表单提交后会写回 `it_asset_request`（或购入申请的 `it_purchase_request`）的 `ding_instance_id / ding_status / ding_synced_at / ding_message`，
   「资产申请」页会显示「钉钉审批中」并隐藏系统内的批准/驳回按钮，避免双通道。
5. 轮询任务（`DingApprovalSyncJob`）默认每分钟触发一次，按配置间隔执行；管理员可在申请页点「立即同步钉钉结果」手动触发。
6. 兜底：未绑钉钉、接口失败、模板未配 → 自动降级为系统内审批并记录原因（`ding_message`），不会卡单。
7. 本地联调（推荐）：`.env` 设 `DINGTALK_ENABLED=true` + `DINGTALK_DEMO_LOGIN=true`，
   这样钉钉接口走真实环境、浏览器仍可用演示账号登录，可直接提交真实申请看钉钉是否收到。
   **生产环境 `DINGTALK_DEMO_LOGIN` 必须是 false**，否则任何人可用姓名登录。
8. 完全不联网时可用「本地联调模式」：申请单会得到 `MOCK-` 前缀实例号，
   管理端「资产申请」页出现「联调：模拟通过 / 模拟驳回」按钮，用来验证整条链路。联调完记得关掉。

前端 `utils/dingtalk.ts` 已封装 `requestAuthCode` 与 `biz.util.scan`，非钉钉环境自动降级为演示模式，不会阻塞本地开发。

## 附件与通讯录同步

**附件**：报修时可传现场截图（最多 3 个、单个 ≤5MB，支持 jpg/png/gif/webp/pdf），
工单详情页可继续补传。文件名为 UUID，按 `{bizType}/{bizNo}/` 分目录存在 `helpdesk.upload.dir`
（默认 `./data/uploads`，可用 `UPLOAD_DIR` 覆盖）。图片用 `GET /api/attachments/raw/{storedName}`
访问，查询、上传、下载和删除均校验所属业务权限；图片/PDF 由前端带认证请求读取后转为 Blob URL 展示，原始地址不再匿名放行。

旧库缺少附件表时，后端启动会通过 `server/src/main/resources/db/attachments.sql` 增量创建，重复启动保留已有记录。
工单详情与附件分别加载；附件失败不会阻塞处理进度，详情和附件各自提供重试入口。
员工首页的「查看进度」与每张「最近工单」均链接到对应详情。
员工首页的四个资产入口（领用 / 借用 / 更换 / 归还）与「资产服务」页使用同一个流程组件
`components/AssetRequestFlow.vue`：卡片样式一致（图标 + 标题 + 可选设备数 + 箭头），
点击就地弹出「选设备 → 填事由 → 提交」，不再跳转到资产页；提交成功后刷新首页数据。
报修表单必填「故障位置」（最多 64 字），建议写明楼栋、楼层和房间/工位；关联设备时仍填写实际故障位置，工单详情显示该填写内容。
前端构建保留旧哈希资源，页面模块失效时自动刷新一次并保留目标工单，持续失败时提供手动重试。
报修时任一级问题分类选中「其他」，会显示「分类补充（选填）」，最多 200 字，留空也可提交；补充内容显示在员工与 IT 的工单详情中。
问题类型联动一级与二级分类：故障报修提供故障项，服务申请提供开通/安装项，咨询提供使用指导项。切换类型重置分类、分类补充和知识推荐，后端验证提交组合。
「系统管理 → 字典与分类」可按三种问题类型分别维护分类；旧自定义分类迁入故障报修，历史工单保持原分类。
`GET /api/meta/categories-by-type` 为报修表单提供分类关系；不带类型的原分类接口仍返回合并字典供列表筛选。
「提交前先看看」的每个推荐知识点都有「已解决」按钮：记录该条知识的有帮助反馈后返回首页，无需创建工单。
反馈失败保留报修内容并支持重试，仍未解决可继续报修；按钮遵循「知识库反馈」权限配置。
`node scripts/employee-ticket-ui-check.mjs` 使用独立浏览器及模拟接口验证电脑、手机入口、类型联动、字典维护、分类选填和失败恢复，不连接业务库或真实钉钉。

**通讯录同步**：`POST /api/admin/sync/dingtalk?mode=dry|demo|live`

| mode | 行为 |
|---|---|
| `dry` | 用内置样例数据只统计不写库，先看会新增/停用多少人 |
| `demo` | 用样例数据真实写库，本地没有钉钉凭据时验证整条逻辑 |
| `live` | 调钉钉开放平台拉真实部门与用户（需 `DINGTALK_ENABLED=true`） |

同步只覆盖姓名、部门、联系方式与在职状态，**不动本地角色**（服务台/工程师/资产管理员在库里配）。
钉钉里已不存在的在职人员会被停用，其名下未结工单自动转派给 IT 主管。同名部门会按名称认领已有记录，
不会同步出重复部门。开启钉钉后每天 02:00 自动跑一次（`DINGTALK_SYNC_CRON` 可改）。

## 已知边界

- SLA 目前按自然小时（P1 4h / P2 8h / P3 16h / P4 40h），与演示版口径一致；正式版需换工作日历。
- 工单由报修人确认解决后自动沉淀知识草稿；IT 默认可以整理，管理员默认可以发布和撤回。公开检索、详情及推荐只展示已发布知识。
- 附件存在本地磁盘，多实例部署需换成对象存储（MinIO/OSS），否则各节点看不到彼此的文件。
- 统计缓存 60 秒，介意实时性可把 `StatsService` 的缓存时间调小。


## 界面：A · Quiet（三角色 / 三栏响应式）

按视觉稿 `../视觉方案/A-Quiet-PC端设计.html` 实装，取代原先「员工端手机布局 + 管理端独立侧栏」两套外壳。

- 统一布局 `web/src/layouts/AppLayout.vue`：顶栏只留品牌、当前角色/页面、搜索、通知、头像，
  **不再有横向导航菜单**；侧栏是唯一主导航。
- 三套菜单在 `web/src/config/menus.ts`：员工 7 项 / IT 9 项 / 管理员 11 项。
  工作区角色由 `roleFromRoles(auth.roles)` 从后端角色推导：
  仅保留普通用户（USER）、IT、管理员（ADMIN）、可查看用户（VIEWER）四种单选角色。
  四个角色均默认拥有首页、本人报修、我的工单、资产领用/借用/更换/归还、知识库及反馈。
  菜单、按钮与后端接口遵循角色权限配置；可查看用户办理本人业务，对其他人的管理数据只读。
  旧权限配置会补齐基础自助能力并保留已配置的管理权限；管理员再次保存后仍可按角色调整。
- 各角色的电脑侧栏共用「我的服务」，手机底栏提供首页、报修、我的工单和资产快捷入口；工作台、工单中心、审批和管理配置保留在对应角色菜单中。
- 断点用 CSS 容器查询 `@container`：≥1200 三栏 208px / 主栏 / 300px；900–1199 两栏且右栏下沉；
  <900 单列 + 底部 Tab（Tab 也按角色不同）。钉钉内自动走单列形态。
- 点顶栏头像可切换演示身份，切换后自动跳到该角色默认页（员工首页 / IT 工作台 / 管理员系统配置）。
- 右栏是真实接口数据：我的申请、知识库推荐、SLA 达成率、工程师工作量、故障分类、
  通讯录同步试跑；接口异常时降级为空，不阻塞主内容。
- 管理员在「系统管理 → 角色权限配置」（`/admin/config?tab=matrix`）按角色勾选权限、恢复默认并保存。
  其他管理分区可按权限委派；角色权限配置入口仅管理员使用且不可取消。
- 回归脚本 `scripts/e2e-check.py` 每次新建一台专用测试资产，可重复执行（当前 37/37 通过）。
