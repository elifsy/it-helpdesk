IT 服务台 · 方案说明 v0.1

资产操作审批流：多节点审批 + 钉钉待办直达

把现在「一个人点一下通过」的资产申请，升级成按业务类型自动匹配的审批链；每一棒落到谁的头上，就在钉钉里给他一张可点开的审批卡片。

2026-11-17 范围：领用 / 借用 / 更换 / 归还 状态：待拍板

01结论与推荐

建议分两层做：审批链在系统内跑，钉钉只负责「喊人 + 一键跳进来」。这样既满足「节点人收到提醒、点一下就审批」，又不依赖公网回调，落地最快。

① 审批流引擎

模板（业务类型 + 条件）→ 实例 → 节点任务。领用走「部门负责人 → 资产管理员」，更换再叠一层「IT 主管」。

② 钉钉提醒

节点生成即推 actionCard 工作通知，按钮「去审批」直达该任务的 H5 审批页（免登，自动带上待办）。

③ 兜底

钉钉推送失败或节点人不在，站内待办 + 首页/侧栏角标照常存在，不会卡死流程。

为什么不一开始就做「钉钉卡片上直接同意/驳回」？
那种按钮需要钉钉回调到公网地址（内网无法直接回调），要额外做内网穿透或公网网关、签名验签、幂等。第一版用「跳转审批」可覆盖 90% 场景，第二版再按需加。

02现状与问题

环节现在的实现缺口
审批能力资产申请一张单，任何一个具备 request.approve 权限的人点「通过」就结束（IT 与管理员默认有该权限）。没有节点概念，谁先看到谁批；部门层面完全不知情。
钉钉通知DingTalkService.sendWorkNotify 已能发 actionCard 工作通知，只带一个「查看详情」链接，链接为空时纯文本。能发卡片，但没有审批任务的深链，点开只能到列表页自己找。
组织数据sys_user 有 dept_id/dept_name，sys_dept 只有名称与父级。没有「部门负责人」字段，主管节点需要先在部门上加 leader（可从钉钉部门主管接口同步）。
资产台账有分类、状态、使用人、借用到期日、购买日期、保修到期。没有「原值/金额」，所以第一版条件规则只能按分类、借用天数、是否跨部门、是否在保判断。

结论：底子够用，主要工作是把「一步审批」换成「按链路推进」，再把钉钉卡片接上深链。

03目标与范围

在范围内（要走审批）

① 资产领用 ② 资产借用 ③ 资产更换 ④ 设备归还
提交即生成审批实例，按模板逐节点流转，任一节点驳回则整单结束并通知申请人。

不在范围内（保持现状）

报修工单仍走 SLA 流程（受理 → 处理 → 完成 → 员工确认），不插人工审批，避免把 4 小时的 P3 拖成 4 天。
可选加强：核心网络/服务器类报修，给 IT 主管发一条「知情提醒」（只通知、不阻塞）。

目标（可验收）

  • 同一张资产申请，按业务类型自动匹配到正确的审批链，节点人和顺序不需要人工指定。
  • 每到一个节点，该节点审批人在钉钉收到一条卡片；点击卡片 → 免登进入审批详情 → 一键通过/驳回，全程不超过 3 次点击。
  • 申请人能在「我的申请」看到当前卡在第几个节点、谁在批，历史节点留痕可追溯。
  • 钉钉消息失败、审批人离职/请假时，流程有人兜得住，不丢单。

04审批流模型

三层结构，模板管规则、实例管单据、任务管人。后续加节点只改模板，不动代码。

模板（规则）

要素说明默认值
适用业务RECEIVE / BORROW / REPLACE / RETURN，一类一条主模板四条内置模板
触发条件按资产分类、借用天数、是否跨部门、设备是否在保匹配；命中「加强条件」则插入附加节点见 05 节
节点链有序节点列表，可标记为「可选节点」（条件不满足时跳过）2–3 个节点
节点审批人部门负责人（按申请人 dept）/ 角色·权限（如 request.approve）/ 指定人部门负责人 + 资产管理员
会签方式依次审批（默认）；或签（该节点多人中任一通过即过）或签
超时节点停留超过阈值 → 催办；再超时 → 升级给上级节点或管理员4 小时催办 / 24 小时升级

兼容：it_asset_request.status 仍保留 PENDING/APPROVED/REJECTED/COMPLETED/CANCELLED，避免影响现有列表与统计；新增 current_node 与节点任务表记录细粒度进度。

06钉钉提醒路线对比

三条路，差别在「点开之后能不能不跳出钉钉」以及「需不需要公网回调」。

路线做法体验代价 / 风险建议
A. 卡片深链
推荐		 节点生成 → actionCard 工作通知（标题/要素/按钮「去审批」）→ 点在钉钉内打开 H5（免登）→ 详情页通过/驳回。 点 1 次进页面，再点 1 次通过，共 2 步 无公网要求，现有 sendWorkNotify 扩展参数即可 P0
B. 卡片内审批 卡片上直接放「同意 / 驳回」两个按钮，钉钉回调到后端接口完成审批。 零跳转，最省事 需公网可达回调地址、验签+幂等+防重放；内网环境要额外穿透 P2
C. 钉钉 OA 审批 调钉钉「发起审批实例」接口，用钉钉原生审批单与待办。 最原生，审批中心统一 需建审批模板、字段映射，审批结果要靠回调/轮询同步回来；两套状态易不一致 备选
建议 A 起步，把 B 的接口留出来。
A 的卡片按钮 URL 用 https://<二维码基址>/#/approvals/task/{taskId}，与现有扫码同一域名，钉钉免登（authCode 换 token）即可带入身份；将来上 B 只需要在同一张卡片换成两个 callback 按钮。

12异常与兜底

钉钉推送失败 / 未绑定钉钉

站内通知照常写入，「资产申请」菜单角标 + 首页待办仍是入口；定时扫描未通知成功的任务补发一次。

审批人离职 / 长期请假

离职停用时自动把其名下 PENDING 任务转给节点的下属/部门负责人；请假由本人在审批列表点「转交」。

部门没配负责人

降级为该部门内具备 request.approve 的人；再没有则直接跳到资产管理员，并给管理员留一条「待补配置」提示。

审批卡住不批

4 小时催办、24 小时升级；管理员有「代审批并留痕」权限，操作记审计日志。

设备被抢 / 库存变化

审批通过执行时二次校验设备状态（复用 assertAllowed），失败则整单回退到「需重选设备」并通知申请人。

重复提交

沿用已实现的「同人同设备一条待审批」校验，审批中再点提交直接拦住。
